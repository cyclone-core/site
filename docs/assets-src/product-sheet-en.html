Are these three problems holding back your integration testing?
01
Fault injection is manual. Pulling cables, patching code, writing one-off scripts — the same fault can never be reproduced precisely a second time, and regression conclusions cannot be aligned.
02
Degradation-chain timing cannot be quantified. Sensor frame drops, delays and data corruption propagate along the chain; there is no quantifiable, assertable way to verify at which millisecond the system degrades, or whether it meets the safety time window.
03
Audit evidence relies on screenshots. ISO 26262 / SOTIF audits demand a traceable, re-checkable evidence chain — not a Word document stitched together from screenshots.

Four Core Capabilities

Capabilities
Deterministic Fault InjectionFaultPipe
Key Differentiator
  • Five fault primitives: Drop (frame drop), Delay, CorruptField (field corruption), Freeze and CorruptCrc (CRC error) cover typical failure modes at the bus and signal layers.
  • Tick-precise triggering: declare trigger points by time window, frame count or conditional expression — the same fault is guaranteed at tick N, with reproduction granularity down to the scheduling cycle.
  • YAML declarative configuration: fault scenarios as code — reviewable, versionable, diffable. No more one-off hand-written scripts.
Deterministic Execution KernelTime Master
  • Dual-mode clock: real-time mode connects to hardware-in-the-loop; virtual-time mode accelerates replay on ordinary servers — the same test case yields identical conclusions in both modes.
  • 1 ms single-threaded deterministic scheduling: identical inputs produce bitwise-identical outputs; test conclusions do not depend on the machine or the moment of execution.
Statistical Assertion VerdictsVerdict Engine
  • Assertions as latching state machines: Pending → Satisfied / Violated / TimedOut — once latched, a verdict never reverts; the verdict process is explainable and auditable.
  • Built-in statistical verdicts: Wilson confidence intervals and SPRT sequential testing turn "ran it a few times, feels fine" into "passed at 95% confidence".
Auditable Evidence ChainEvidence Chain
Key Differentiator
  • Four artifacts produced automatically: case hash (unique scenario identifier) + SHA-256 log digest + failure-scene snapshot + JUnit XML report.
  • Designed for audits: every test conclusion traces back to a specific case version and its raw data; supports third-party re-verification and plugs directly into CI regression dashboards.
